## 今回やったこと

### 1. Vercel新規プロジェクト作成でのハマりどころ

GitHubリポジトリ`kenny19790413/tool-dev`（モノレポ、ツール開発ルート全体）をVercelにImportし、Root Directoryを`stock-portfolio`に設定してデプロイを開始したが、複数の問題が連続して発生した。

#### 問題1: Framework Presetが「Other」のまま検出され、ビルド失敗
- 初回ビルドで`middleware.ts`の`next/server`・`jose`・`process`が軒並み「モジュールが見つからない」エラー
- 原因調査の結果、プロジェクトの Settings → General → Build and Deployment で **Framework Presetが「Other」になっていた**（本来は自動でNext.jsになるはずが誤検出）
- 手動で「Next.js」に変更して保存 → 解決

#### 問題2: ルートの`.gitignore`で`package.json`が全プロジェクト共通で除外されていた（重大・横断的なバグ）
- Framework Preset修正後も「No Next.js version detected」エラーが継続
- 調査の結果、**ツール開発ルート直下の`.gitignore`に文字化けしたコメント付きの重複「Node.js」セクションがあり、`package.json`/`package-lock.json`が全プロジェクト共通でgit管理から除外されていた**
- このため`stock-portfolio/package.json`が一度もコミットされておらず、Vercelがpackage.jsonを認識できずNext.jsプロジェクトと判定できなかった
- ルートの`.gitignore`から該当行（`package.json`/`package-lock.json`/重複した`node_modules/`）を削除し、`stock-portfolio/package.json`・`package-lock.json`をコミット・push（コミット`52ab48f`）
- **横展開の確認**: `meishi-order`・`meishi-order-kanko`もpackage.jsonがgit管理下に無いことを発見したが、これらは`tool-dev`とは別の**独立したGitリポジトリ**（`.git`ディレクトリが個別に存在）であり、ツール開発ルートの`.gitignore`とは無関係と判明。それぞれ専用の`.gitignore`を持っており、既に本番稼働中のため今回は深追いせず保留（次回以降、必要なら別途調査）

#### 問題3: Prisma Clientが本番ビルド時に生成されずビルド失敗
- package.json修正後、ビルドはコンパイルまで進むようになったが「Collecting page data」の段階で`Cannot find module '.prisma/client/default'`エラー
- ローカル開発では`npx prisma generate`を手動実行していたため気づかなかったが、Vercelのビルドではこの工程が自動化されていなかった
- `package.json`の`build`スクリプトを`"next build"`→`"prisma generate && next build"`に変更（コミット`74b4be1`）
- ローカルで`npm run build`を実行し成功することを確認してからpush

## 開発中に踏んだハマりどころ（技術メモ）

### Vercelの「Framework Preset」誤検出
モノレポでRoot Directoryを指定してImportする際、初回はFramework Presetが正しく自動検出されないことがある。Settings → General → Build and Deployment Settings で手動で「Next.js」を選び直し、保存する必要がある。

### モノレポ共通`.gitignore`でのpackage.json除外事故
`ツール開発`ルート直下の`.gitignore`に、誰かが（別プロジェクト用に？）追加したと思われる`package.json`除外設定が残っており、新規プロジェクト（stock-portfolio）がその影響を受けて長時間デバッグする羽目になった。**モノレポ共通の`.gitignore`に`package.json`や`package-lock.json`を書かないこと**（Node.jsプロジェクトでは必須ファイルであり、除外すべきではない）。

### VercelビルドではPrisma Clientの自動生成が保証されない
`prisma`パッケージのpostinstallフックに頼らず、`package.json`の`build`スクリプトで明示的に`prisma generate && next build`としておくのが安全。ローカルでは`npx prisma generate`を都度手動実行していると、この抜け漏れに気づきにくい。
