# StockPortfolio 作業記録 2026-08-07

## 全体ステータス

新規プロジェクトとして0からスクラッチ構築。ダッシュボード・資産CRUD・株価/配当/投資信託基準価額の自動取得・パスワード変更・証券会社記録・外貨(USD)建てプライベート資産・証券会社スクリーンショットのAI画像解析による一括登録まで実装済みでローカル動作確認済み。実際の保有資産（単株・プライベートファンド十数件）も登録済み。**未デプロイ**（Vercel未作成）。

## 今回やったこと

### 1. プロジェクト新規作成（printquote構成を踏襲）

- `../stock-portfolio` に Next.js 15 + TypeScript + Tailwind v4 + Prisma 7 + Neon(PostgreSQL) + JWT認証 の構成で新規作成
- shadcn/ui コンポーネント（button/input/card/table/badge/dialog/select/tabs等）をprintquoteから流用
- 対象資産: 単株（日本株・米国株）／債券／ファンド／プライベート資産（未公開株等）を一元管理

### 2. Prismaスキーマ

- `Asset` — type(STOCK/BOND/FUND/PRIVATE), market(JP/US, 株のみ), ticker, quantity, avgCost, currentPrice, dividendPerShare, broker, note
- `Valuation` — 非上場資産（債券/ファンド/プライベート）の手動評価額履歴
- `ExchangeRate` — USDJPY為替レート取得履歴
- `Credential` — ログインパスワードのハッシュ（単一レコード）

### 3. 株価・配当・為替取得（`lib/stock/yahoo.ts`）

- Yahoo Finance非公式APIを利用（公式APIではないため将来的に仕様変更のリスクあり）
- 現在値取得: `v8/finance/chart` エンドポイント（crumb不要、安定）
- 配当取得: `v10/finance/quoteSummary`（cookie+crumbが必要）
- 銘柄検索: `v1/finance/search`（cookie+crumbが必要）
- **判明した制約**: 検索APIは日本語（かな漢字）クエリを受け付けず400エラーになる。銘柄コードかローマ字/英語社名のみ対応。UIとエラーメッセージに明記済み。

### 4. 認証

- 当初は`APP_PASSWORD`環境変数と平文比較する簡易実装だったが、「パスワードを変えるところがない」という指摘を受けてDB管理に変更
- `Credential`テーブルにbcryptハッシュで保存。初回アクセス時に環境変数`APP_PASSWORD`の値でレコードを自動作成し、以降は`/settings`画面からアプリ内でパスワード変更可能
- JWT(`sp_token`, 30日, HttpOnly Cookie) + middlewareで全ページ保護

### 5. 画面・機能

- ダッシュボード（`/`）: 総資産（円換算）・年間配当見込み・資産クラス別内訳（円グラフ、recharts）・為替レート表示・一括更新ボタン
- 資産一覧（`/assets`）: 種別タブ切り替え、評価額・損益・配当を一覧表示
- 資産追加（`/assets/new`）: 単株は銘柄検索→選択で自動取得、非株式は評価額を手動入力
- 資産詳細（`/assets/[id]`）: 個別の価格更新・編集・評価額履歴追加・削除
- 設定（`/settings`）: ログインパスワード変更

### 6. UI調整（ユーザーフィードバック反映）

- 含み損益の色: 当初は日本の株式相場の慣習（赤=上昇/緑=下降）で実装していたが、「利益を緑、損益（損失）を赤で」との指示で一般的な配色（緑=利益、赤=損失）に変更
- 「どこの証券会社で買ったか」を記録したいとの要望で`Asset.broker`フィールドを追加。追加フォーム・編集フォーム・一覧・詳細に反映

### 7. 投資信託（FUND）対応

- 投資信託協会「投信総合検索ライブラリー」は**利用規約で自動取得（スクレイピング）を明記して禁止**していたため使用不可と判断（WebSearchで利用規約を確認）
- 代わりに、運用会社の公式ファンドページURLをユーザーが貼り付け、HTMLから「基準価額」を正規表現で抽出する方式で実装（`lib/stock/fundNav.ts`）
- `Asset.fundUrl`追加。評価額計算は「基準価額(1万口あたり)÷1万×口数」（`FUND_NAV_UNIT`定数）
- 三井住友DSアセットマネジメント（smd-am.co.jp）の実URLで動作確認済み。運用会社によっては対応できない可能性がある旨をUIに明記
- 登録フォームに「確認」ボタンを追加し、登録前に基準価額をプレビュー表示

### 8. 米ドル建て資産対応（BOND/PRIVATE）

- 「米国のプライベート・クレジットやプライベート・エクイティ・ファンドにも対応してほしい」との要望
- `Asset.currency`（JPY/USD）を債券・プライベート資産の登録時に選択可能に。`Valuation.value`はJPY固定ではなく資産の`currency`建てとして解釈するよう`calcAssetValueJpy`を変更（USDは為替レートで円換算）
- `Valuation.value`の精度を`Decimal(18,0)`→`Decimal(18,2)`に変更（USDは小数点以下が必要なため、マイグレーション実施）
- $250,000のテスト資産で円換算表示を確認済み

### 9. 投資信託の米ドル建て対応の検討（実装は見送り、重要な調査結果あり）

ユーザーの実例URL（大和アセットマネジメント「ダイワ・ブラックストーン・プライベート・クレジット・ファンド（米ドル建て）」https://www.daiwa-am.co.jp/funds/detail/0876/detail_top.html ）を調査：

- ページ自体は「外国籍投資信託のため、各種データを表示していません」と明記 → HTML上に基準価額なし
- ただし月次レポートPDFには基準価額データが含まれていた（Node.js + `pdf-parse`でテキスト抽出、Pythonは未インストールのため使用不可）
- 抽出結果: 基準価額 99.07米ドル、分配金再投資基準価額 122.94米ドル、純資産総額2,066百万米ドル（基準日2026年5月31日、**公開から約2ヶ月遅れ**）
- **課題**: PDFが複数カラムレイアウトのため、pdf-parseのテキスト抽出だと列の中身が混ざり、どの数字がどの項目か文脈判断が必要だった。運用会社ごとにPDFレイアウトが異なるため、汎用ロジックでの自動抽出は誤読リスクが高いと判断し、**実装を見送り**
- ユーザーから「証券会社はどこから日次価格を取得しているか」と質問があり、機関投資家向け有償データフィード（Bloomberg/Refinitiv等、ファンド管理会社との直接契約）であり個人が無料で同じ経路を使うことはできない旨を説明
- ユーザーから岡三証券のオンライン取引システム（omni-net.okasan.co.jp、ログイン+パスキー認証必須）のURLが提示されたが、**証券会社ログイン情報を保存する自動ログインスクレイピングは実装しない旨を明確に説明し、了承を得た**（実資金にアクセスできる認証情報を扱うリスク、パスキー認証で技術的にも困難、規約違反の可能性）
- **結論**: この種の非上場・低頻度更新の私募ファンドは「プライベート資産（米ドル）」で月次PDFを見ながら手動更新する運用に確定

### 14. 開発サーバー競合による事故と復旧

作業中、ユーザーが使用中だったポート3000のdevサーバーと、動作確認用に別途起動したdevサーバーが同じ`.next`ビルドキャッシュに同時アクセスし、Windows特有の`EINVAL: readlink`エラーで`.next`が破損。ポート3000がInternal Server Errorになった。該当プロセスを終了し`.next`を削除して再起動することで復旧（**DBデータへの影響はなし**）。教訓：同一プロジェクトで複数のdevサーバーを同時起動しない。

## 開発中に踏んだハマりどころ（技術メモ）

### `@prisma/adapter-neon` の正しい使い方
`PrismaNeon`コンストラクタには**接続文字列を含む設定オブジェクト**を渡す必要がある。

```ts
// 誤り（両方とも動かない）
new PrismaNeon(neon(process.env.DATABASE_URL!))       // ✗ neon()のタグ関数を渡す
new PrismaNeon(new Pool({ connectionString: url }))    // ✗ Poolインスタンスを渡す

// 正しい
new PrismaNeon({ connectionString: process.env.DATABASE_URL })  // ✓ 設定オブジェクトを渡す
```

誤った実装だと`No database host or connection string was set...(user: kenny, db: kenny)`という紛らわしいエラーになる（OSユーザー名にフォールバックするため一見DB接続情報がまるごと無視されたように見える）。

**⚠️ printquoteの`lib/db/client.ts`も`new PrismaNeon(sql)`という誤った書き方になっている**（`neon()`のタグ関数を渡している）。動いているように見えても実際にはDB接続に失敗している可能性があるため、次回printquoteを触る際に確認・修正推奨。

### `@prisma/adapter-neon`のバージョン差異
`^7.8.0`のキャレット指定だと7.9.1が入り、これは動作確認していない組み合わせ。printquoteと合わせて`7.8.0`に固定（package.jsonでキャレット無し）。

### Windows Git Bashでの日本語curlテスト
`curl -d '{"name":"トヨタ..."}'`のように日本語を直接コマンド引数に書くと文字化けしてDBに化けた文字列が保存される（Git BashのOSコードページ変換の問題）。JSONファイルに書いてから`--data-binary @file`で送ると回避できる。ブラウザのfetch経由では問題なし。

### この開発環境にPythonは未インストール
`python`コマンドはMicrosoft Storeのスタブを指すのみで実際には使えない（`py`ランチャーも無し）。PDF処理などPython前提の作業はNode.js（`pdf-parse`等のnpmパッケージ）で代替する。

### 開発サーバー再起動を忘れると実データ登録が失敗する
Prismaスキーマ変更後（`npx prisma generate`だけでは不十分）、既に起動中の`next dev`プロセスは新しいPrisma Clientを認識しない。スキーマ変更のたびに`npm run dev`を再起動必須。一度、`broker`フィールド追加後に再起動を忘れ、ユーザーの実際の資産登録が3回失敗する事故があった（後続の別作業での再起動で偶然解消、データ損失はなし）。
また`.next`キャッシュが破損してreadlinkエラーで起動失敗することがあった → `.next`ごと削除して再起動で解消。
